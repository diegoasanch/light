# CYW43439 firmware blobs

Firmware for the CYW43439 WiFi chip inside the board's Murata LBEE5KL1YN-814
(Type 1YN) module. Loaded at runtime by the `cyw43` driver via
`cyw43::aligned_bytes!` in the wifi test binaries.

`cyw43` crate version):

## History note (the 2025 bug)

The previous `43439A0.bin` / `43439A0_clm.bin` in this directory were **GitHub
404 HTML pages** saved from dead URLs, not firmware — one of the reasons WiFi
never came up. If a blob ever looks ~286 KB and starts with `<!DOCTYPE html>`,
it happened again. When upgrading the `cyw43` crate, refresh these blobs from
the matching `cyw43-vX.Y.Z` tag and update the table above.

## NVRAM caveats

`nvram_rp2040.bin` is the Pico W/2W board profile, required by `cyw43 >= 0.5`
as the third blob. Its digital/gSPI side matches this board (xtalfreq=37400
matches the 1YN's embedded crystal), so detection/scan/join should work — but:

- Its **RF calibration** (TX power tables etc.) was characterized for the
  Pico W's bare CYW43439 + trace antenna, not the Murata 1YN module with this
  board's antenna. If bring-up succeeds but RSSI is weak or joins are flaky,
  obtain Murata's official Type 1YN NVRAM and add it as a fourth pinned blob
  (the embassy dir at the tag shows the pattern: `nvram_sterling_lwb+.bin`,
  generated by `write_nvrams.rs`).
- It ships `ccode=ALL` (worldwide-safe regulatory profile): channels 12/13 are
  restricted. An AP on those channels may be invisible to scans.
- It ships a **generic `macaddr`**; the module's OTP usually overrides it, but
  with 4 assembled boards, verify each reports a unique MAC before putting
  several on one LAN.
